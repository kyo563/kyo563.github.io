プライバシーポリシー

2026年10月3日 / 作者・運営：kyo563 / お問い合わせ：joinqueue.bot@gmail.com

本ポリシーは、待機列整理アプリ（わんコメ連携版）と共通Bot「JoinQueue Bot」の接続・通知機能に適用します。本サービスはYouTube API Servicesを使用します。現在の情報の取り扱いを以下に説明します。

1. 利用者のPCで処理・保存する情報

わんコメから受け取ったコメントを解析し、参加者情報、ハンドル・表示名・申告名、待機列、参加履歴、わんコメのメモ、表示設定、必要な接続情報をPC内へ保存します。再起動後の復元と待機列の管理に使用します。わんコメのGoogleログイン情報やパスワードを取得することはありません。

2. 配信者のGoogle認証

チャンネルの所有と接続許可を継続して確認するため、Googleの認証画面でYouTubeの読み取り専用権限（youtube.readonly）を要求します。Google公式APIのchannels.list（mine=true）で所有チャンネルIDを確認します。GoogleのパスワードはGoogleに入力し、本サービスへ入力する必要はありません。

配信者のアクセストークンは処理中にだけ使用し、継続保存しません。更新用のリフレッシュトークンはサーバーだけで暗号化保存し、接続許可の再確認とGoogleへの権限解除要求に使用します。配信者用の認証は共通Botの投稿用認証とは別のGoogle Cloudプロジェクトで管理します。配信者・BotのGoogle認証情報をプラグインや他の配信者へ渡すことはなく、コメント取得にも使用しません。

プラグインには本サービス専用の端末接続キーを保存し、Windows DPAPIで保護します。認証中は、不正な接続を防ぐため、有効期間10分の認証用Cookieと確認番号を使用します。旧方式から移行する場合は、新しい情報の取り扱いを確認して再認証してください。

開始前の配信枠のチャット接続先を通常の動画情報だけで確認できない場合は、配信者の読み取り専用認証でGoogle公式APIのliveBroadcasts.listを使用し、わんコメで選択した動画IDの配信情報だけを取得します。所有チャンネル、終了していないこと、チャットIDを確認するために使い、チャットIDは処理中のみ使用します。配信者の認証でコメントを取得・投稿したり、配信を開始・変更したりはしません。APIで接続先を確認できない場合はBot接続を許可しません。

3. Bot通知のためサーバーへ送る情報

Bot機能を使う場合、端末認証情報、配信ID、通知種別、投稿に必要な表示名・ハンドル名、待機順、グループ番号、人数などを共通バックエンドへ送ります。配信の所有者と稼働状況を検証し、要求された通知をYouTubeライブチャットへ投稿します。投稿した文面は対象ライブチャットで公開されます。

受信コメント履歴の全体、わんコメのメモ、フォントファイルを共通Botサーバーへ送ることはありません。コメントの取得はわんコメが行い、共通Botサーバーで重複取得しません。

共通Botの投稿用権限（youtube.force-ssl）は運営者がBot用アカウントで認証します。この権限を配信者のチャンネル接続時に要求することはありません。Botの秘密情報・リフレッシュトークンはサーバー側で暗号化保存し、利用者へ配布しません。

4. サーバー保存情報と利用期限

暗号化した配信者の更新用認証情報、確認済みチャンネルID、利用者・接続・端末識別子、端末キーのハッシュ、認証確認日時、最終利用日時、失効状態、投稿要求の識別子・時刻・ハッシュ・処理結果を保存します。接続管理、不正利用の防止、投稿先検証、レート制限、連投・重複防止、不具合調査に使用します。投稿台帳へ投稿本文そのものを保存しません。

サーバーへの通信元について、不正な認証要求の制限に用いるハッシュ値を一時的に保存します。診断ログには要求識別子・状態・エラーコード等を記録し、Googleのトークンやパスワードを記録しません。

接続の利用期限は、最後の有効な利用から90日です。プラグインからの認証済み接続状態確認、対象配信の接続確認、正当なBot投稿要求で利用日時を更新します。サーバーの自動認証チェックや、PC内の待機列・OBS表示の利用だけでは延長しません。90日間利用がなければBot接続は利用できなくなり、次回は再接続が必要です。Google側の権限解除・期限切れ等でも再認証が必要になります。

所有チャンネル情報は原則24時間ごとに再確認し、更新できない状態が29日続けば接続を停止します。認証の一時的な通信障害時もBot投稿を止め、誤投稿を防ぎます。

本番の期限による記録の自動削除と「サーバー記録を削除」機能は、現在無効です。90日未利用による利用停止と、保存記録の削除は別です。利用停止だけで暗号化認証情報・接続記録・投稿台帳が自動削除されるとは限りません。削除のお問い合わせは次の項目をご確認ください。一般提供の開始前に保存期限・削除の運用を確定し、本ページを更新します。Google OAuth審査は未完了で、現在の認証はテスト対象者に限られます。

5. 接続解除・データ削除に関するお問い合わせ

プラグインのBot設定で接続を解除すると、対象チャンネルのサービス接続を停止し、Googleへ更新用認証情報の失効を要求します。Googleから解除成功を確認した後、サーバーの暗号化した配信者認証情報を削除します。一時的な通信障害時は解除成功とせず、再試行のため暗号化認証情報を保持します。解除が完了するまでBot接続は停止します。

接続解除だけで過去の接続記録や投稿台帳がすべて消えるわけではありません。PC内の待機列・OBS設定、共通Botの認証情報、他の配信者の保存記録は削除しません。PCの端末接続キーはプラグインが解除完了を確認したときに削除します。

PC内の保存データは設定画面の完全初期化で削除できます。サーバー側の保存情報の削除については、joinqueue.bot@gmail.comへご連絡ください。対象チャンネルの特定と所有確認が必要です。問い合わせ時にGoogleパスワード、OAuthトークン、端末キーを送らないでください。

Googleによる本サービスへのアクセス許可は、Googleアカウントのサードパーティ接続設定からも取り消せます。サーバーは定期確認または次の利用時に失効を検出し、対象接続を停止します。Googleでの解除だけでサーバーの過去の記録がすべて消えるわけではありません。同じGoogleアカウントの複数チャンネルを接続した場合、Googleでの解除が他のチャンネルの認証にも影響し、再接続が必要になることがあります。

本サービスの保存データを削除しても、YouTubeにすでに投稿された通知は自動的に削除されません。YouTube上のデータの管理はYouTube側の機能をご利用ください。

6. 外部サービスと情報共有

接続と投稿にGoogle/YouTube、バックエンドの通信・保存基盤にCloudflare、案内サイトの配信にGitHub Pagesを使用します。これらの提供者はサービスの運営・保護のために通信情報等を処理する場合があります。Googleユーザーデータを広告目的で販売したり、第三者のAIモデルの学習へ提供したりすることはありません。

Google APIから受け取った情報の利用・他のアプリへの転送は、Limited Use要件を含むGoogle API Services User Data Policyに従います。

Privacy summary in English

Developer/operator: kyo563. Contact: joinqueue.bot@gmail.com. Queue data and OneComme memos are stored locally. Creator authorization uses youtube.readonly to verify channel ownership and continued permission. Creator access tokens are not persisted. Refresh tokens are encrypted on the server for permission checks and Google revocation, never distributed to the plugin or used to receive comments. Creator authorization uses a separate Google Cloud project from the shared Bot's operator-only youtube.force-ssl authorization. The local device key is protected with Windows DPAPI. A ten-minute cookie protects the authorization flow.

Notification requests contain the destination stream and the names/queue information necessary for the selected notification. The backend does not receive all comment history, OneComme memos or font files. It stores encrypted creator refresh credentials, connection IDs, verified channel IDs, credential hashes, verification/activity timestamps and posting metadata/hashes/results, not the full notification text. Cloudflare hosts the backend; GitHub Pages hosts this site; Google/YouTube provides authorization and chat posting.

Connections expire after 90 days without valid authenticated plugin activity. Background checks and local queue/OBS use alone do not extend this period. Ownership data is normally refreshed every 24 hours; a 29-day failure to refresh stops the connection. Permission expiry or revocation can require earlier reauthorization. Automatic retention deletion and the server-record erasure feature remain disabled in production: inactivity stops use but does not automatically erase all credentials or historical records.

Disconnect stops the channel's service access and requests Google revocation. Encrypted creator credentials are removed after successful revocation; transient failures retain them for retry. Historical records, local queue/OBS settings and shared Bot credentials are not erased by disconnect. Contact the operator for deletion enquiries without sending passwords or tokens. Google access can also be revoked using the Google Account permissions link above; checks detect revocation and stop the connection. Revocation can affect other channels authorized under the same Google account. Deleting service data does not delete messages already posted on YouTube. Existing creators must reauthorize for this new handling. Google OAuth verification is not yet complete and authorization remains limited to test users.

Our use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

For upcoming streams without a chat ID in the public video metadata, the server uses creator youtube.readonly authorization with liveBroadcasts.list for only the selected video ID. It checks the owner, non-ended state and chat destination. Chat IDs are used in memory only. Creator authorization never receives/posts chat messages, starts streams or changes broadcast settings. If the API cannot verify the destination, Bot connection is refused.
